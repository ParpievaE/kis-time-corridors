Задача о проходе ориентированного графа. Вершины обозначают места, а направленные рёбра - временные коридоры, по которым можно перемещаться только в указанном направлении. У коридора есть длительность, необязательный дедлайн и список требований к предметам. Все требования одного коридора соединены логическим "и". Циклы и повторное посещение вершин допускаются.

### Обозначения переменных

- `T_lim` - максимально допустимая продолжительность миссии.
- `T_cost` - стоимость одной единицы личного времени; значение должно быть больше нуля.
- `start_time` - момент начала миссии. В выбранном формате он целочисленный и может быть отрицательным, нулевым или положительным.
- `time_jump_i` - длительность i-го пройденного коридора.
- `w_time` - абсолютный момент прибытия в текущую вершину.
- `duration` - продолжительность миссии, используемая в ограничении и расчёте выгоды.
- `value_j` - ценность j-го предмета.
- `deadline` - крайний допустимый момент прибытия в конец коридора.
- `[A, B]` - временное окно, в течение которого предмет можно собрать.

### Формулы, возникающие в моем предположении постановки задачи

Для маршрута, начинающегося в момент `start_time`, момент прибытия в вершину после прохождения нескольких коридоров рассчитывается так:

`w_time = start_time + сумма(time_jump_i)`

Продолжительность миссии учитывает и величину сдвига момента старта относительно нуля, и время движения по коридорам:

`duration = abs(start_time) + сумма(time_jump_i)`

Миссия укладывается в ограничение по времени, если `duration <= T_lim`. При этом `w_time` - абсолютный момент времени, а `duration` - величина, которую нужно минимизировать и которая используется при расчёте выгоды.

Если у коридора задан дедлайн, проверяется момент прибытия в его конечную вершину: `w_time <= deadline`. Равенство дедлайну допустимо. Требования к предметам проверяются до прохождения коридора.

Предмет автоматически и мгновенно собирается при посещении своей вершины, если момент прибытия попадает в его временное окно. Границы окна включительны: `A <= w_time <= B`. Если окно не задано, предмет доступен при любом времени посещения. Ожидание в вершине не предусмотрено, а один предмет учитывается в выгоде не более одного раза. В моем предположении постановки задачи достижение любой выходной вершины немедленно завершает миссию.

Выгода маршрута рассчитывается по формуле:

`profit = сумма(value_j собранных предметов) - duration / T_cost`

Минимальная продолжительность и максимальная выгода вчисляются независимо: эти показатели могут соответствовать разным допустимым маршрутам.

Временные значения во входном формате задаются целыми числами; перебираются целочисленные значения `start_time` от `-T_lim` до `T_lim` включительно.

### Коминтарий о восприятии примера из условия

В формальном описании задачи не сказано, что успешная миссия обязана собрать хотя бы один предмет. Однако изходя из исходного примера можно предположить, что заказчик считает, что хотябы один предмет должен быть собран, и я буду сходить из этого допущения. 

Так же я буду считать что во последнем пункте ответа в примере в услвии задачи заказчик допустил оплошность, в том плане что при прохождении описанного в примере маршрута, если действительно "Миссия начинается в момент времени 0", то это противоречит тому, что артефакт в вершине 1 успешно собрался. Всвязи с этим в нашей постановке буду считать что в примере была ошибка и времнного окна для данного артефакта не подразумевалось. ```

## Запуск

```bash
./build/kis-time-corridors < input.txt
```

## Формат входных данных

1. `T_lim T_cost`.
2. `N M K P` - количество вершин, коридоров, предметов и выходов.
3. Идентификатор начальной вершины `start_node`.
4. `P` идентификаторов выходных вершин.
5. `M` строк коридоров: `from to duration deadline requirement_count artifact_id...`. Символ `-` означает отсутствие дедлайна. Идентификаторы предметов во входных данных начинаются с 1.
6. `K` строк предметов: `node value window_start window_end`. Пара `* *` означает отсутствие временного окна.

Идентификаторы вершин начинаются с 0.

### Тестирование

Реализованы четыре автоматических теста для проверки основных сценариев работы алгоритма: недостижимость выхода в несвязном графе, превышение допустимого времени миссии (`T_lim`), нарушение дедлайна коридора и невозможность завершить миссию без сбора артефакта при недоступном временном окне его получения.

Запуск тестов выполняется командами `cmake --build build` и `ctest --test-dir build --output-on-failure`.

Программа сообщает выполнимость миссии, минимальную продолжительность и максимальную выгоду. Если допустимой миссии нет, для двух оптимизационных показателей выводится `none`.
